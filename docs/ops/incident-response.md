## 1. 事件分级

| 级别 | 定义 | 示例 | 响应时限 |
|------|------|------|----------|
| P1 重大 | 服务不可用、数据泄露/丢失、被入侵 | 数据库被拖库、图纸批量泄露、勒索加密 | 15 分钟内响应 |
| P2 严重 | 核心功能受损但有绕行方案 | 转换服务宕机可重启恢复、权限误配导致越权访问 | 1 小时内响应 |
| P3 一般 | 单点异常、性能劣化、告警类事件 | 定时任务失败（系统自动产生 `task_run_failed` 告警） | 当日处理 |

（响应时限为制度默认值，公司确认项见总单 CF-19）

## 3. 处置流程（通用）

1. **发现与上报**：监控告警 / 用户反馈 / 例行审查 → 记录发现时间与现象，通报【待公司：CF-08 应急群组】；
2. **抑制与止损**：必要时隔离主机、封禁 IP（走 IP 黑名单机制，操作自动留痕）、停用账号（`USER_DEACTIVATE` 自动留痕）；
3. **根除与恢复**：修复漏洞/清除持久化后门，按 [backup-restore-policy.md](backup-restore-policy.md) 恢复数据与服务；
4. **取证**：保护审计日志与应用日志，导出相关时间段审计记录（导出动作本身留痕），**不得删改原始日志**；
5. **总结**：3 个工作日内出具事后报告。

> **告警链路**：系统 P1 告警（备份校验/恢复演练/异地推送失败、恶意代码检出等）由 `AlertNotificationService` 聚合发送邮件至【待公司：CF-10 告警邮件收件人】（backend `.env` 的 `ALERT_EMAIL_TO`，需 `ALERT_EMAIL_ENABLED=true`）；监控栈告警经 Alertmanager 同址发送。

## 4. 典型场景速查

| 场景 | 首要动作 |
|------|----------|
| 疑似账号被盗 | 冻结账号 → 强制改密 → 审计日志回溯该用户近期操作 |
| 越权/提权迹象 | 回放 `PERMISSION_GRANT` / `ROLE_UPDATE` 审计 → 回收多余授权 |
| 数据误删 | 项目/节点优先从回收站恢复（`NODE_RESTORE`）；超出回收站按备份恢复流程 |
| DDoS / 扫描攻击 | 启用 IP 黑名单 + 网关层限流；留存攻击日志 |

## 5. 事后报告模板

- 事件编号/级别/时间线（发现—响应—恢复）
- 影响范围（用户数/数据量）
- 根因分析
- 处置措施与证据清单（含审计日志摘录）
- 整改项与责任人、完成期限
