一、目标与方法

以「深模块 / 唯一出口 / 消灭重复 / 删除孤儿」为核心视角，对 monorepo 做迭代式复审：每轮用技能视角扫描出结构性问题（重复实现、浅模块、死代码、越权防线缺口），修复后以测试 + 类型检查为门禁验证，再进入下一轮，直至一轮复审不再发现新问题。所有改动遵循 AGENTS.md 的「外科手术式修改」与「三层一致性」原则——只动必须动的行，且确认前端 / API SDK / 后端 / 数据库无需联动。

收敛原则：≥3 份重复即缺陷，收敛到唯一出口；无消费者代码删除或标注；安全类重复（权限判定）必须收敛到 fail-closed 的单一断言出口，杜绝「较弱的第 N 份」绕过主线。

三、任务明细（16 项）

安全 / IDOR 防线

安全#1batch-download createTask IDOR 修复 + assertNodeAccess 唯一出口
批量下载建任务时任意登录用户可传他人 nodeId 建任务，引擎真实转换并产出 ZIP。新增 FileSystemPermissionService.assertNodeAccess 作为服务层节点访问断言的唯一出口（fail-closed：库根要求 LIBRARY_*_MANAGE、项目/个人空间按权限存储判定、根不可解析即拒绝），建任务与文件夹展开统一走它。
验证：新增 15 例 IDOR 回归测试，后端全绿。
安全#12mxcad-file-access 业务逻辑下沉 + MIME 4 份收敛
controller 里的手写业务逻辑下沉到 MxcadFileAccessService（controller 只做路由委托）；散落的 MIME 判定 4 份收敛到 NodeUtils 单一出口。
验证：后端 2685/2685 + 13 例 IDOR 回归全绿。
安全#16cross-node assertDownloadPermission 收敛到 assertNodeAccess
跨节点批量 ZIP 的 assertDownloadPermission 是较弱的第 4 份节点访问断言——只判项目 owner / FILE_DOWNLOAD，不处理库根与个人空间，且与单文件下载口径不一致。改为委托 assertNodeAccess，补齐 fail-closed 语义（库根现正确要求 LIBRARY_*_MANAGE）。owner 直通由权限存储内部保证，行为等价；spec 重写为「委托成功 / Forbidden 重抛 / 非 Forbidden 记错误条目 / 缺节点跳过」四例。
验证：后端 196/2690 全绿，含 #1 的 IDOR 回归锚点。

四、最终复审（一轮无新问题）

孤儿扫描：对移动端 composables / utils / hooks / command 与 PC lib / hooks / utils 做零消费者文件扫描。命中的 46 个 command/m_mx_* 均为误报——命令文件由 main.ts 的 import "./command" 副作用导入触发、经 addCommand 自注册；PC 的 hooks/*/index.ts 为按目录导入的 barrel。真实孤儿仅 useShellMode，已在 #15 删除。
重复扫描：对已收敛的唯一出口（formatShareExpiry / useLongPress / triggerBlobDownload）复扫，均为「单出口 + 多消费者」的健康形态；ShareManagePage 的 formatDate（纯日期「创建时间」，对齐 PC createdAt 列）与 formatShareExpiry（有效期文本）是不同格式，非重复。isInUploadsCache（单 util + 3 消费方）与 sanitizeZipName（job-context 单一定义 + 3 调用点）核实已收敛、无隐藏内联副本。
三层一致性：本轮所有改动均为内部重构或死代码删除，未触及任何 DTO / 端点契约——checkFileExist 响应形状 { exists, nodeId } 不变，cross-node 为服务内部重构，移动端为内部逻辑——故无需重新生成 API SDK，前端 / 移动端无联动。
