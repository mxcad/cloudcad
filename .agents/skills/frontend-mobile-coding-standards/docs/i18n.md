# i18n 国际化（VoerkaI18n）

移动端（frontend_mobile）使用 **VoerkaI18n**，与 PC 端（frontend）同方案。本文是移动端 i18n 规范，与 `packages/frontend_mobile/AGENTS.md` ③ i18n 铁律一致。

## 工作流

新增任何中文 UI 文案的完整流程：

```bash
# 1. 代码里用 t('中文') 包裹（禁止手动加 id）
pnpm i18nExtract    # 2. 自动提取中文到 default.json + 自动分配 id 到 idMap.json
#   3. 在 messages/en-US.ts / zh-TW.ts / ko-KR.ts 补对应语言翻译
pnpm i18nCompile    # 4. 编译生成产物
pnpm build          # 5. 构建（自动包含 i18n 编译）
```

## 使用规则

### Vue 模板中

```vue
<template>
  <van-button>{{ t('按钮文本') }}</van-button>
</template>
```

### TypeScript 中

```typescript
const { t } = useI18n();  // 或项目统一的 t 导入
const label = t('文件名');
```

变量插值传第二参数：`t('剩余 {days} 天', { days: 3 })`，**禁止 `.replace()` 手动替换**。

## ⚠️ 铁律：禁止模块级 t() 烘焙

`src/languages/index.ts` 中非中文语言包（en-US/zh-TW/ko-KR）全是**动态 import（异步）**。模块求值期 en-US pack 尚未就绪，`t()` 必然回退同步 zh-CN——**模块顶层的 `t()` 结果会被烘焙成中文，切语言后永不刷新**（实例：`useProjectAuditLog.ts` 的 `ACTION_LABELS`、`projectPermissions.ts` 的 `PROJECT_ROLE_NAMES`，2026-11-03 修复）：

```ts
// ❌ 模块顶层——求值时烘焙成中文
const ACTION_LABELS: Record<string, string> = { FILE_CREATE: t('新增图纸') };

// ✅ 函数式 getter——渲染期求值；switch + t() 字面量让 extract 自动登记
export function actionLabel(action: string): string {
  switch (action) { case 'FILE_CREATE': return t('新增图纸'); default: return action; }
}
```

- 修复模式：静态标签表 → 函数式 getter；零散文案 → 移入组件 setup / composable 函数体
- **消费方自愈合免修**：烘焙值的消费方若在渲染期再包一层 `t(bakedValue)`，主方向自愈，不要修——下结论前先 grep 消费点
- 修完跑 `pnpm i18n` 并**重启 Vite**（内存缓存旧模块，页面会显示裸数字 id，刷新无效）
- 完整审计/验证工作流（静态扫描、残留分类、浏览器 CJK 扫描）见 `frontend-i18n-audit` 技能

## ⚠️ 铁律：禁止手动加 i18n key

新增任何中文文案，**只写 `t('中文')`，禁止手动添加 id**：

1. **写入代码**：用 `t('新的中文文案')` 包裹，不用管 id 是多少。
2. **自动提取**：`pnpm i18nExtract` —— voerkai18n 扫描 `t('中文')` 自动把新文案提取到 `default.json`，并自动分配新 id 到 `idMap.json`。
3. **补翻译**：对新 key 在 `messages/en-US.ts` / `zh-TW.ts` / `ko-KR.ts` 补对应语言翻译。
4. **自动编译**：`pnpm i18nCompile` 生成编译产物。

**禁止**（手改这些文件会把 extract 的自动分配打乱、产生重复/冲突 id，下次 extract 会漂移）：

- 禁止手动往 `idMap.json` 加 `"中文文案": 数字` 条目。
- 禁止手动往 `messages/*.ts` 加 `"数字": "译文"` 条目。
- 禁止手动改 `default.json`（会被 extract 覆盖）。

验证：新文案提取后 `idMap.json` 应自动多出 `"中文文案": <新id>`，且 `messages/*.ts` 的 id 连续递增，无手工插入痕迹；凡 diff 里出现手插 id 条目即违规。

## 文件结构

```
src/languages/
├── messages/
│   ├── default.json    # 中文默认（extract 自动写入，勿手编）
│   ├── zh-CN.ts        # 中文
│   ├── en-US.ts        # 英文
│   ├── zh-TW.ts        # 繁体
│   └── ko-KR.ts        # 韩文
├── idMap.json          # 中文文案 → id 映射（extract 自动分配，勿手编）
└── index.ts            # i18n 初始化
```

## 语言切换

```typescript
import { setCurrentLanguage } from '@/languages';
setCurrentLanguage('en');  // 切换到英文
```

语言列表：zh-CN（默认）/ en-US / zh-TW / ko-KR。

## 非源码文本

自定义/非源码提取文本（如引擎 mxUIConfig）写入 `translates/messages/mxUIConfig.json`；`default.json` 会被 extract 覆盖，勿手动编辑。
